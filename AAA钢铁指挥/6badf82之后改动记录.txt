1. 背景音乐音量滑块(56557c4 → e9ff80a 重构)
   - 初始(56557c4):
     * index.html 设置面板新增 #musicVolume range(0~100,默认 60)
       和 #musicVolLabel。
     * music.js 新增 musicVolume=0.6,setMusicVolume() 实时写入
       musicEl.volume,并持久化 localStorage['ra_volume']。
     * css/style.css 新增 .setVolume 滑块样式。
   - 最终形态(e9ff80a):
     * 删除 musicOn/toggleMusic/setMusic 和设置面板开关按钮,
       滑块滑到 0 即静音。
     * 拆出 musicVolPct(滑块百分比 0~100)与 musicVolume(实际 0~1)。
     * 映射公式(感知均匀):
         x = pct/100
         volumeFromPct(p) = (x + log10(1 + 9*x)) / 2
       即线性曲线与对数曲线取中值;ra_volume 仍存滑块百分比,
       默认显示 60,实际增益约 0.70。
     * 切歌(selectMusic)、initMusic、playMusic 都统一使用 musicVolume。

2. 飞机/机场逻辑修复(e9e1413)
   - 出售机场释放停驻飞机:
     * update.js 抽出公共函数 releaseParkedAircraft(b):
       遍历 units,凡 u.homeBase===b && u.parked 的飞机改为
       parked=false,patrol=机场废墟点,order=none,清 _returning/_returnBase。
     * destroyBuilding 与 build.js sellBuilding 都调用它,
       解决"出售机场后 F-16/苏-27 永久卡在停驻、凭空消失"。
   - 母港丢失后转投新机场:

     * orders.js 右键己方机场时:
         dest = (u.homeBase && u.homeBase.alive) ? u.homeBase : 点击机场;
         _returnBase = (dest===homeBase) ? null : dest;
       homeBase 已死/已出售也能发起返场。
     * updateAircraft 返场优先使用 _returnBase(且要求 alive 且仍在
       buildings 列表),到达 60px 内检查新机场停机位(AIRFIELD_CAPACITY),
       有空位才 parkAircraft。

       disabled,提示"未安装导弹包";面板属性行也显示该提示。

11. 寻路脱困全面优化(d650fb7)——重点
   A. 友军软障碍绕行(path.js)
      - queuePath(u,tx,ty,order,detour):_pendingPath 增加 detour 标记。
      - processPathJobs:detour 任务不参与流场统计;处理时走
        pathForDetour,否则走原 flow/A* 逻辑。
      - pathForDetour(u,tx,ty):
        * 复制通行掩码(passableMaskFor(u).slice());
        * 把 240px 内友军/同盟单位(非敌人、非飞机)的胶囊 AABB
          (两圆圆心 ±(colR+4))标为不可通行;
        * 新建 MapGrid + AStarPathfinder 重算,再 smoothPath;
        * 不进普通 pathCache,避免单位位置变化导致缓存失效。
   B. 卡死优先级(update.js)
      - applyMovement 本地脱困:
        * 先判 staticBlocked=uBodyBlocked(u,u.x,u.y);
        * 纯同伴拥堵(!staticBlocked 且 detour 未失败):直接
          queuePath(...,true),不再左右乱顶;
        * 静态卡死或 _detourFail(0.5s 内)才走 14/26/40px 侧移;
        * 真被埋住(中心格 !unitPassable,或胶囊两圆所在格都堵):
          立即 pullOutOfObstacle;
        * 仅擦边时用 _edgeStuckT 累计,>=1s 才允许瞬移(第二位),
          之后旋转脱困,最后再兜底瞬移。
      - resolveStuckAfterRigid:
        * 航点卡死(wpStuck)最后航点时重排 detour 路径;
        * 位移不足且纯同伴拥堵时直接排 detour 并 return;
        * 静态卡死/绕行失败才侧移。
   C. 瞬移出口两遍搜索(update.js findExitCellFor)
      - 第一遍(pass=0):要求出口格无友军占用(hasUnitOverlapAt);
      - 第二遍(pass=1):放宽到静态可通行即可,墙角被围死也能瞬移出;
      - 第一遍若已有"中心可走"兜底就直接用,不瞬移到友军身上。
   D. 防挤入建筑角(update.js)
      - separateAll:每个分离推力方向先探测 4px,若 uBodyBlocked
        (朝向建筑/水面)就剔除该方向分量,避免友军把人压进墙角。
      - resolveRigid:先按权重分别尝试双方位移;若双方都放不下,
        让能动的单位吃下整段穿透量(pen),避免"墙角单位动不了、
        挤它的单位也动不了"的双钉死。
   E. 验证
      - node --check 全部通过;
      - Node 情景测试 8 项全过(见第三节)。

五、后续开发注意事项
------------------------------------------------------------
1. 音量映射是"线性+对数取中值"经验公式,若觉得低区/高区仍不均,
   可改 volumeFromPct 权重(如 0.6 线性 + 0.4 对数),不要改滑块存值。
2. pathForDetour 有 1 秒冷却(_detourT),大团战 100+ 单位同时卡住时
   每个单位最多 1 秒重排一次,仍可控;若卡顿,可把 240px 缩小或
   只对 attack/move 指令启用。
3. findExitCellFor 第二遍会瞬移到"中心格可走但可能贴近友军"的格,
   是最后手段;正常路径下第一遍无友军占用优先,不会频繁瞬移。
4. 攻击续战索敌 240px 是全局常量,想做成"单位档案可配置"时可挪到
   config.js 或单位 def 上。
5. 飞机逻辑是独立体系(updateAircraft/planMission),地面寻路脱困的
   改动不会自动套用到飞机;后续若飞机也出现卡顿,需单独排查。
