================================================================================
《钢铁指挥》坦克类 / 步兵战车修改经验总结
（基于:美洲狮 puma / 艾布拉姆斯 abrams / T90 / 布拉德利 / 黄鼠狼 / B11 /
  豹2A4 leopard / 勒克莱尔 leclerc / 挑战者 challenger / M60 / T54 的实际改动）
================================================================================

本文件记录在本项目中"给坦克/步兵战车加新单位、改贴图结构、改战斗逻辑"时踩过的坑
和沉淀下来的经验。所有结论都以当前代码为准,改代码前先通读下列要点。

--------------------------------------------------------------------------------
一、新增一辆步兵战车/坦克的完整步骤
--------------------------------------------------------------------------------
1. 数据配置(js/config.js)
   - UNIT_BOX:碰撞箱半宽/半高。坦克是长条形,取 hw(半长) > hh(半宽),
     例如 puma:{hw:33, hh:13},abrams:{hw:36, hh:15}。
     碰撞圆半径 colR = min(hw,hh),头尾圆心距 colOff = max-min(见 Unit 构造)。
   - getUnitDefs(阵营)[type]:血量/速度/射程/伤害/射速(秒/发)/造价/半径/护甲/
     弹丸类型/说明。阵营专属单位只写进对应阵营的 defs(盟军/苏军),另一方自然
     拿不到,天然做"阵营隔离"。
   - transportCost():占运输艇多少点。加新战车务必补进去,否则默认只占 1 点。
   - crushesTrees():重型单位可碾树。轮式 IFV 通常不碾(视需求)。
   - TRACK_UNITS():是否留履带/轮辙压痕。要压痕就加 type:1。
   - IMAGES:贴图映射(必须加,preloadImages 会遍历 IMAGES 加载)。
   - SPRITE_SCALE:照片贴图额外缩放;SPRITE_ROT:贴图"自然朝向"对齐角(见下)。

2. 生产限制(js/build.js)
   - canTrain() 与 canProduceIn():凡是"需升级战车工厂"的单位,都要把 type 加进
     那份高级单位清单(abrams/t90/mcv/bradley/b11/marder/leclerc/leopard/
     challenger/puma...)。漏加=升级工厂也造不出来。
   - js/ui.js 里选中工厂后显示的"可生产列表"(盟军/苏军两组)也要同步加。

3. 其余索引
   - js/map.js 的 KNOWN 白名单(自制地图能否摆放该单位)。
   - map-editor.js 的 UNIT_TYPES / UNIT_LABEL(地图编辑器素材栏)。
   - index.html 帮助文本(可选)。

4. 版本号
   - config.js 的 GAME_VERSION 要 +1,index.html 所有 <script> 的 ?v=xx 全部同步
     +1,map-editor.html 也要 +1。否则浏览器缓存旧代码,改了半天看不到效果。

二、素材处理(tools/process-sprite.js)与朝向约定
--------------------------------------------------------------------------------
1. 挖白底:用洪泛填充只剔除"与图片边缘相连"的背景,不伤车体内部深色/高光。
   命令示例:
     node tools/process-sprite.js "源图.png" 输出名 img/units 512 旋转角
   - 输出目录:单位贴图放 img/units,建筑贴图放 img。
   - 旋转角:90/180/270 为"顺时针"。想要逆时针 90° 就传 270。
   - 自动按内容居中/裁切,超过最大尺寸等比缩小。

2. 朝向约定(关键,决定了渲染里的 rotOff):
   - "车头朝上"贴图(如 puma 车身/炮塔、25mm 子弹):渲染时额外转 +π/2。
   - "水平向右为正方向"(如 TOW 导弹):渲染时转 0,直接沿角度画。
   - "水平向左为正方向"(如艾布拉姆/T90 车身与炮塔、125mm 炮弹):
     渲染时转 +π(或 -π)。
   - 记法:贴图正方向在图像坐标里的角度 = imageFrontAngle,
     渲染总旋转 θ 需满足  imageFrontAngle + θ = facing,
     其中 facing=0 是屏幕 +x 方向。
       车头朝上:  imageFrontAngle = -π/2  → θ = facing + π/2
       水平朝左:  imageFrontAngle =  π   → θ = facing + π
       水平朝右:  imageFrontAngle =  0   → θ = facing

3. 阴影(render.js drawShadowSprite):
   - 用"车体贴图黑色剪影 + 高斯模糊"做 L 形投影:相对车体只偏移一点点
     (UNIT_SHADOW_L_OFFSET,默认 {x:4,y:6}),露出右下 L 形黑边;
     不透明度约 0.45,边缘模糊,不要用纯黑实心矩形/AO 圆。
   - 阴影大小 = 车体贴图渲染大小(用同一缩放公式算 dw/dh),自动随 SPRITE_SCALE
     变化;所以整体缩放时阴影也会跟着缩放,不用单独调。

三、车身 + 独立炮塔结构(仿美洲狮)
-------------------------------------------------------------------------------
★方向约定(改炮塔位置前先记牢,以下全按此口径)★
   - 车头方向 = 车身/炮塔贴图的"正方向" = 炮管所指方向。代码里 +facing 即车头。
   - "炮塔向前 / 向车头移动 Npx" = 沿车头方向(+facing)平移 → turretRotCenter 加 N。
   - "炮塔向后 / 向远离车头移动 Npx" = 沿车尾方向平移 → turretRotCenter 减 N。
   - 炮塔的"正方向端"就是炮管所在的那一端;几分之几法则里"距炮口 k×贴图长"
     也是以这一端为起点算的。
-------------------------------------------------------------------------------
1. 为什么要独立炮塔:让炮塔 360° 独立瞄准,车体不用整个转过去对敌,
   手感更像现代坦克。当前独立炮塔单位:puma / abrams / t90 / tank(M60·T54)/
   bradley / b11 / leclerc / leopard / challenger(isTurretUnit 判定)。

2. 渲染(render.js drawHullTurretUnit):
   - 车身:ctx.rotate(facing) 后按 rotOff 旋转整张贴图(朝前)。
   - 炮塔:旋转中心(座圈)在车身中心沿车头偏移 turretRotCenter(u,tw) 处,
     绕它朝 turretAng 独立旋转:
        ctx.translate(turOff,0);       // 座圈沿车头(+facing)前移,负=偏车尾
        ctx.rotate(turretAng - facing + rotOff);
        ctx.drawImage(img, -w/2-pivX, -h/2-pivY, w, h);
     其中 pivX/pivY 由"几分之几法则"算出(见 §三.3),让座圈落在旋转点上。
   - 开火闪光画在炮塔图"前端",相对旋转点:fx = tip[0]*w - pivX, fy = tip[1]*h - pivY。
     (车头朝上贴图 tip=[0,-0.5];水平向左贴图 tip=[-0.5,0];车头朝下 tip=[0,0.5])

3. ★几分之几法则(turretPivotK,config.js)—— 本条最重要★
   - 概念:炮口 = 贴图正方向端。旋转点(炮塔环/座圈)距炮口的距离 = 贴图长轴 × 系数 k。
       k=2/3  → 距炮口 2/3 贴图长(经典默认,长炮管转向不甩大圈)
       k=1/2  → 旋转点=贴图正中心(美洲狮/布拉德利)
       k=3/5、7/10、4/5 → 介于之间按车微调(如 T54 反复试后定为 4/5)
   - 代码实现:config.js 的 turretPivotK(u) 返回各车 k(默认 2/3;可按阵营/车单独
     改)。render.js 里旋转点相对贴图中心沿长轴的偏移 = (k - 1/2) × 长轴:
        水平朝左 pivX=+(k-1/2)*tw; 水平朝右 pivX=-(k-1/2)*tw
        车头朝上 pivY=+(k-1/2)*th; 车头朝下 pivY=-(k-1/2)*th
   - 同理,开火弹丸出生点 = 旋转点 + 沿炮塔朝向伸出 k×贴图长
     (update.js fireAt:muzzleDist = 轴长 × turretPivotK(u) + 2),必须跟渲染里
     的炮口闪光位置保持一致。
   - 经验:把"2/3→1/2"等于把旋转点沿炮口方向前移 1/6 贴图长(当前贴图下约几 px)。
     用户说"旋转点向炮口方向移 Npx",多半就是调 k,而不是调座圈位置!两者要分清:
        - 座圈位置(turretRotCenter)= 整门炮塔相对车身中心的前后平移;
        - 旋转点/法则(turretPivotK)= 炮塔贴图内部绕哪一点转(影响转向甩动幅度)。
     改错目标会得到"炮塔平移了但转向照样甩大圈"的效果。
   - 注意:turretRotCenter 只沿车身中线前后移,不会让炮塔横向偏;k 只改贴图内部
     旋转点,不移动座圈。M60/T54 共用 type='tank',改 k 必须按阵营分支。

4. 三个缩放层级(全在 config.js),按用户需求只动对应一个:
   - SPRITE_SCALE:整体缩放(车身+炮塔一起)。tank 按阵营用 unitSpriteScale(u)
     (M60 0.85 / T54 0.765),其余直接查表。
   - SPRITE_BODY_SCALE:仅车身缩放(炮塔不动),与整体相乘 = 实际车身大小
     (如 tank 车身额外 0.85)。
   - turretScale(u):仅炮塔缩放(车身不动),如 T54 炮塔额外 0.81。
   - 联动:阴影(drawShadowSprite)按"整体×车身"算,保证阴影跟车身实际大小;
     fireAt 的炮口距离按"整体×炮塔"算,保证弹丸从炮口出。只改一处缩放会
     出现"阴影大车身小 / 弹丸不对炮口"。

四、独立炮塔的战斗逻辑(update.js,isTurretUnit 分支)
--------------------------------------------------------------------------------
1. 炮塔只在"索敌/开火"时主动旋转:
   - 每帧 _turretAiming 复位为 false;
   - 攻击指令有存活目标、或移动中朝射程内敌人开火时,才把 _turretAiming 置 true
     并用 lerpAngle 把 turretAng 拉向目标(转角速度 PUMA_TURRET_RATE)。
   - 无索敌时,炮塔以同样转速缓慢转回车头方向(turretAng → facing),
     而不是瞬间跳回(瞬间回位很难看)。

2. 开火条件(最关键的行为):
   - 目标在射程内:车体停住(不移动、不倒车、不被挤),炮塔持续对准目标;
     只有当 |angDiff(turretAng, 目标方向)| <= 对准误差(PUMA_TURRET_ALIGN)
     才开火 —— "炮口对着敌人才开火"。
   - 目标在射程外:炮塔边转,车体边寻路逼近;进入射程后车体停住只转炮塔打。

3. 车体不参与瞄准:
   - applyMovement 里 aiming 判断对 isTurretUnit 一律为 false;
   - 车体朝向只跟移动方向(wantVx/wantVy);原地攻击时保持当前朝向。

4. 战斗钉住(_standFire):
   - 射程内原地射击的单位会:清空倒车/滑出/让行,强制 wantVx=0,不被分离力推挤,
     也不参与方向仲裁倒车 —— 解决"战斗时乱跑乱动找位置"。
   - 重要:移动指令(玩家点地面,含撤离)的优先级高于战斗钉住 —— 只让"攻击指令"
     触发钉住,移动单位正常走,途中可边走边打(攻击移动 x2 保持原样)。

五、弹丸替换与速度函数(update.js fireAt + render.js drawProjectiles)
--------------------------------------------------------------------------------
1. 25mm 机炮弹(bullet_25mm.png,车头朝上):
   - 作用单位:美洲狮/布拉德利/黄鼠狼/B11(isIFV25)。
   - 士兵子弹 = 25mm 贴图的 0.5 倍长(只给北约士兵/动员兵,即 infantry)。
   - 速度:先加速后匀速 —— 初速 = 最大速度 ×IFV_START_FACTOR(0.25),
     每帧按 IFV_ACCEL 加速到上限(update 弹体循环里 if(p.accel) 加速)。
   - 渲染:贴图 + 曳光拖尾(亮芯+泛光,弹尾向后渐隐)。

2. 125mm 坦克炮弹(shell_125mm.png,水平朝左):
   - 作用单位:所有主战坦克 tank/abrams/t90/leclerc/leopard/challenger
     (isTankShellUnit),含商业体进驻坦克位(updateGarrisonAttack 里也要打标)。
   - 长度渲染 18px,等比缩小;旋转 ang+π 让车头朝左的贴图对准飞行方向。
   - 速度:从发射起匀速(不加速),直接命中目标。
   - 渲染:贴图 + 曳光拖尾,看起来是高速炮弹而非贴图平移。

3. 反坦克导弹模块(ATGM,独立 Missile 类):
   - 美洲狮/黄鼠狼/布拉德利可装($150,6秒,装填15秒,射程180,单发300)。
   - 导弹是"类单位":独立存在,自动制导(每帧朝目标当前位置稍微转弯)、
     被路径上敌方单位挡下立即爆炸、目标阵亡瞬间自爆、超射程自爆。
   - 伤害:直击目标(或被挡者)吃单体满伤,周围小范围(ATGM_AOE_RADIUS)其它
     单位/建筑吃 50% 范围伤害。
   - 弹种是 'missile',伤害修正走独立表 MISSILE_MOD(铸铁/钢甲120%,钛合金90%,
     布/木/混凝土80%)。
   - 速度也是先加速后匀速。导弹/子弹这些"运动过程"都要加渲染(尾烟/曳光),
     不能只是贴图移动。

--------------------------------------------------------------------------------
六、开火相关杂项
--------------------------------------------------------------------------------
1. 所有坦克/载具开火不再产生后坐力位移:删掉 fireAt 里
   `u.fireRecoil = FIRE_RECOIL` 那一句,车身就不会开火时抖一下。
2. 炮口/弹丸出生点:
   - 普通单位:车体中心 + facing 方向伸出 u.r+4。
   - 独立炮塔单位:炮口 = 座圈(turretRotCenter 沿 facing 偏移)+ 沿炮塔朝向
     伸出"k × 贴图长轴"(k=turretPivotK;美洲狮/布拉德利 1/2,T54 4/5,其余 2/3)。
     要跟渲染里的炮口闪光位置保持一致。
3. 速度函数"先加速后匀速"统一做法:给 Projectile 加 maxSpeed/accel 字段,
   初速=maxSpeed×起始系数,update 里每帧 min(maxSpeed, speed+accel*dt)。

--------------------------------------------------------------------------------
七、卡死/建筑卡住的兜底(update.js)
--------------------------------------------------------------------------------
1. pullOutOfObstacle / findExitCellFor:
   - 每 0.8s 检查一次单位中心格,若被建筑/障碍压住(不可通行)就拉到最近可通行格。
   - 卡死脱困(左右/后退/旋转)全部失败时也调用它兜底。
   - 这不改 astar/path 寻路本身,只是脱困;若要去动寻路务必先跟用户说明。

八、踩坑清单(随手记)
--------------------------------------------------------------------------------
- process-sprite 输出的旋转是"顺时针";要逆时针转 90° 记得传 270。
- 贴图朝向(车头朝上/朝左/朝右)决定 rotOff,搞错会整辆坦克横着走。
- 旋转点不改的话,长炮管炮塔转向时"甩大圈",很丑;用"几分之几法则"修正
  (默认 k=2/3;想轻一点就调大 k 逼近 1,想贴中心就调小到 1/2)。
- 炮塔前后位置(turretRotCenter)与旋转法则(turretPivotK)是两个东西:
  前者平移整门炮塔,后者改贴图内部绕点;用户说"旋转点/法则/几分之几"=改 k,
  说"座圈/向车头车尾移 Npx"=改 turretRotCenter,别搞混。
- 方向约定:车头 = 正方向 = 炮管方向。"向前/向车头" = turretRotCenter 加 N,
  "向后/向远离车头" = 减 N。报数值时先确认"当前值 + 目标方向",避免正负搞反
  (本项目多次因正负号反了来回改)。
- 缩放有三层:整体 SPRITE_SCALE(坦克按阵营走 unitSpriteScale)、仅车身
  SPRITE_BODY_SCALE、仅炮塔 turretScale。改完必须同步阴影和炮口距离,
  否则出现"阴影大车身小 / 弹丸不对炮口"。
- M60/T54 共用 type='tank':任何按车(非按阵营)的改法都要加
  `unitFactionOf(u.team)==='soviet'` 分支,否则两车一起变。
- ★改 UTF-8 中文文件(如 index.html)别用 PowerShell 的 Get-Content/Set-Content:
  默认按 ANSI 编解码会直接把中文写成一堆乱码(本项目真实事故)。要批量替换
  版本号等,用 Node:`fs.readFileSync/…replace…/writeFileSync` 或直接编辑工具。
- 炮塔前移量有正负:负值=偏车尾。用户报"太靠前/太靠后"时,直接说当前数值,
  让用户报目标值,避免反复猜方向。
- 加了新单位忘加 version 号,浏览器一直加载旧 JS —— 改动无效的第一嫌疑。
- 战斗"钉住"只对攻击指令生效;玩家移动/撤离指令必须永远优先生效。
- 阴影/比例/炮口全都要跟最终缩放联动,否则缩放后阴影和炮口对不上。
