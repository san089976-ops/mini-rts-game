《钢铁指挥》装甲升级包具体事项
（反坦克导弹 + 自主防御 + T84BM双模块 + 空军武器/雷达/涂层 的经验与逻辑总结）
===============================================================================

本文件记录"升级包"类功能(目前有:反坦克导弹模块 TOW/长钉、自主防御系统 APS、
T84BM 反应装甲模块、T84BM 红外干扰装置、空军 A-120c/A-174b 导弹包、雷达火控、
涂层更新)的完整逻辑、代码位置和踩坑经验。改代码前先通读。

| 涂层更新      | F16/苏35                    | 1200 | 15秒 | 被动(敌方探测-50) |
升级包的通用套路(每个升级包都按这套来):
  - entities.js Unit 构造里加一组字段:
      xxx(已装) / xxxUpgrading(安装中) / xxxProg(进度) / 可选 xxxReload(装填)、xxxAmmo(弹夹)
  - build.js 写 startXxxUpgrade(u):校验(可装类型/已装/安装中/资金)→扣钱→置 installing。
  - update.js updateUnit 里:每帧推进 xxxProg,到时间置 xxx=true + 特效 + updatePanel();
    再跑运行时逻辑(武器装填/探测/发射)。
  - ui.js:unitStatsHTML 加属性行;updatePanel 里加按钮(mkAction)。
  - input.js 按钮 action 分发(startXxx / toggleXxx)。
  - config.js 加全部常量 + isXxxUnit(u) 判定。
  - 版本号 +1(index.html 全部 ?v= 同步,见总经验文件)。

二、反坦克导弹(TOW / 长钉)
--------------------------------------------------------------------------------
1. 两类导弹是"两种不同的导弹",靠 spriteType 区分(不是一套!):
     TOW   = 布拉德利/黄鼠狼发,贴图 tow_missile(28px)
     长钉  = 美洲狮发,贴图 spike_missile(25px)
   发射打标:launchATGM 里 `u.type==='puma'?'spike':'tow'`。
   渲染选图:drawMissiles 里 `m.spriteType==='spike' ? spike : tow`。
   拦截过滤:APS 只反 spriteType==='tow' 的(见第三节)。
   千万别把两个导弹并成一个"反坦克导弹"来处理——拦截逻辑、命名、贴图都按
   spriteType 分叉。命名辅助函数(config.js):
     atgmMissileName(spriteType)  → 给飞弹显示名(TOW导弹/长钉导弹)
     atgmTypeName(u)              → 给单位显示名
     atgmModuleName(u)            → 给安装模块按钮名(TOW导弹模块/长钉导弹模块)

2. 导弹是"类单位":存在全局 missiles 数组(state.js),不在 units 里。
   Missile 类(entities.js):x/y/target/team/attacker/spriteType,
     先加速后匀速(speed 初速=ATGM_SPEED×起始系数,maxSpeed/accel),
     每帧向目标当前位置"稍微转弯"(ATGM_TURN_RATE 限转角),
     目标死亡→原地爆炸、超射程(ATGM_RANGE)→自爆、
     路径上有敌方单位挡路(atgmBlocker)→撞上爆炸、命中目标→爆炸。
   伤害:命中目标(或挡路者)吃单体满伤,周围 ATGM_AOE_RADIUS 内吃 50% 范围伤,
     弹种 proj='missile' 走独立修正表 MISSILE_MOD。

3. 安装/发射:
   - 可装类型:ATGM_TYPES=['puma','bradley','marder']。
   - 装填:单发,ATGM_RELOAD=15 秒;装好后攻击指令里目标在 ATGM_RANGE(180) 内
     且装填就绪才 launchATGM(u, at)。
   - AI 也会装(ai.js 检查 ATGM_TYPES),注意给 AI 留余钱判定。

4. 踩坑:名称辅助函数必须全定义!ui.js 用过 atgmTypeName 而 config 漏定义,
   一点安装按钮 updatePanel 就 ReferenceError(真实事故)。加函数/常量后 grep
   一遍所有引用点。

三、自主防御系统(APS:反 TOW 导弹)
--------------------------------------------------------------------------------
1. 设计:艾布拉姆专属升级包。被动探测"进入反应圈"的敌 TOW 导弹,发射反导弹拦截,
   防止自身/友军被 TOW 打中。只反 TOW,不反长钉,不反己方。

2. 常量(config.js):
     APS_TYPES=[abrams]         APS_COST=500        APS_UPGRADE_TIME=12
     APS_MAX_AMMO=4(弹夹)       APS_RELOAD=16(每发填充)
     APS_RANGE=220(反应圈半径)  APS_HIT_R=14(命中判定)
     APS_COUNTER_SPEED=ATGM_SPEED×2(420,反导弹=反坦克导弹的一倍)
     APS_COUNTER_LEN=10(反导弹渲染长,贴图照用 25mm 子弹)
     isAPSUnit(u)

3. 运行逻辑(update.js,updateUnit 内):
   - 安装:apsUpgrading 推进 → 装好置 aps=true,apsOn=true,apsAmmo=APS_MAX_AMMO。
   - 填充:apsAmmo<上限 时每 APS_RELOAD 秒补 1 发(apsReload 倒计时)。
   - 探测/发射(关键):只有"新进入圈内的敌 TOW 导弹"才各打一发——
       a. 只算敌方:isEnemy(u.team, m.team)(m.team=发射方队伍)。
       b. 只反 TOW:spriteType==='spike' 直接跳过。
       c. 只打新来的:用 u.apsEngaged[] 记录已接战导弹,命中过的跳过;
          每帧先清掉已消失(dead/不在 missiles)的记录,防数组膨胀。
       d. 打一发即 break(本帧最多一发),扣 1 发弹夹、开始 16s 填充。
   - 开关:apsOn 布尔,选中后按钮切换;关闭时跳过探测(填充照常)。
   - 没有"再次接战":同一枚导弹只拦截一次;若反导弹追不上(超射程自毁)不再补射。

4. 反导弹(Interceptor 类,entities.js):独立数组 interceptors(state.js)。
   - 目标 = 来袭导弹对象(targetMissile),追踪其当前位置(限转角),先加速后匀速,
     速度 = APS_COUNTER_SPEED(420)。
   - updateInterceptors(update.js):目标已消失→自毁;命中(dist<=APS_HIT_R+4)→
     interceptMissile:把来袭导弹 dead=true(不再造成伤害)+ 爆炸特效;超射程自毁。
   - 渲染 render.js drawInterceptors:贴图 bullet_25mm(车头朝上,旋转 ang+π/2),
     绿色曳光,与普通飞弹区分。
   - 循环顺序:updateMissiles 先动飞弹,updateInterceptors 再追(才能追最新位置)。

5. UI/表现:
   - 选中艾布拉姆:未装→「自主防御系统 $500」;已装→「开启/关闭 + 反导弹 x/4」。
   - 选中开启 APS 的艾布拉姆,画 220px 虚线反应圈(drawSel)。

6. 踩坑:
   - ★"一遇到飞弹就全射光":若只按"圈内有敌 TOW 就发射",导弹一直停在圈内,
     每帧都打一发直到弹夹耗尽。必须用 apsEngaged 记录"已接战",一次只发一发。
   - 反导弹必须 > 来袭导弹速度才有意义:取 2×ATGM_SPEED。
   - 敌我判定用 m.team(发射方队伍),不是 m.attacker,也不是目标队伍。
   - 拦截后要立刻把来袭导弹 m.dead=true,否则它继续飞行还会爆炸伤人。
   - 新增升级包后:config 常量、entities 字段、build 安装函数、input 按钮、
     ui 面板、update 运行时、版本号,六处缺一不可。

四、T84BM 反应装甲模块(300 护盾,每秒恢复 10)
-------------------------------------------------------------------------------
1. 设计:T84BM 苏军重坦专属升级包(被动防御)。给单位一层 300 点的护盾,
   优先于血量承受伤害,每秒恢复 10 点(被打破后也能从 0 重新生成)。
   与 T90 的"反应装甲"科技(REACTIVE_SHIELD=300,回 15/秒,一次免死)不同:
   T84BM 是独立模块,恢复更慢、没有免死。两者都复用 u.shield 字段。

2. 常量(config.js):
     RARM_COST=300           RARM_UPGRADE_TIME=15
     T84BM_SHIELD=300        T84BM_SHIELD_REGEN=10
     RARM_TYPES=['t84bm']    isRarmUnit(u)

3. 运行逻辑(update.js):
   - 安装:startRarmUpgrade(build.js)→ updateUnit 推 rarmProg → 装好置
     rarm=true、u.shield=T84BM_SHIELD(直接给满盾)。
   - 恢复:if(u.rarm && u.shield<T84BM_SHIELD) u.shield = min(300, +10*dt)。
   - 承伤:applyDamage 里把盾吸收逻辑从"仅 t90"改成"任意单位 shield>0 都吸收"
     (否则 T84BM 的盾完全不生效,真实坑)。
   - 护盾条/光环:drawUnit 按 u.shield>0 自动画(盾环+血条上方护盾条),无需新代码。
   - UI:unitStatsHTML 护盾行的回血数值按单位动态取(T90 回15 / T84BM 回10)。

4. 踩坑:
   - 复用 shield 字段,别新建字段——否则 applyDamage 里还要多一处分叉。
   - applyDamage 的盾吸收 if 原来写死 type==='t90',加新盾单位必须放宽容。

五、T84BM 红外干扰装置(前方 120° 扇形干扰敌 TOW)
-------------------------------------------------------------------------------
1. 设计:T84BM 苏军重坦专属升级包(被动防御)。以自身为原点、**炮塔朝向**为前方,
   张开 120° 扇形、半径 180px。敌方 TOW 导弹一进入即被打上"干扰"标记:导弹
   失去制导,按随机方向每飞约 16px 换一次向,乱飞 3 步后自动爆炸;一旦被干扰
   则永久生效(离开干扰区也继续乱飞)。对长钉无效、对我方导弹无效。

2. 常量(config.js):
     IR_COST=200              IR_UPGRADE_TIME=15
     IR_TYPES=['t84bm']       isIRUnit(u)
     IR_RANGE=180(扇形半径)   IR_ANGLE=Math.PI*2/3(120°)
     IR_STEP=16(每步距离)     IR_STEPS=3(满3步爆炸)

3. 运行逻辑(update.js):
   - 探测(updateUnit 内,if(u.ir && u.irOn) 分支):遍历 missiles,命中条件 =
       未 dead/未 jammed/spriteType==='tow'/敌方(m.team 是敌队)/
       距离 ≤ IR_RANGE/方向与炮塔夹角 ≤ IR_ANGLE/2。
     命中即 m.jammed=true;jamSteps=0;_jamStepD=0;m.ang=扇形内随机起始向;break。
     **每帧最多干扰 1 发**(一次 break),与 APS 同思路。
   - 开关:irOn 布尔(装好默认开启),选中后按钮「红外干扰装置:开启/关闭」切换
     (input.js 'irToggle');关闭时跳过探测。drawSel 扇形也只在开启时画。
   - 被干扰导弹(updateMissiles 顶部 if(m.jammed) 分支):
       _jamStepD 累加 m.speed*dt,每满 IR_STEP 就换一次随机方向(jamSteps++);
       jamSteps≥IR_STEPS → explodeIRJam(不分敌我爆炸)。
       期间每帧做 irJamBlocker 碰撞判定,撞到任意单位/建筑(不分敌我,飞机除外)
       → 立即 explodeIRJam,被撞者吃满伤。
   - explodeIRJam:与普通 explodeATGM 不同——AOE 范围伤**不分敌我**
     (友军、发射者都可能被炸),只有飞机免疫(维持"所有单位打不到飞机")。
     普通 TOW 的 explodeATGM 是"只打敌方+免发射者+免飞机",二者刻意区分。
   - 扇形方向用 u.turretAng(炮塔):坦克接战时炮塔朝目标,干扰区就罩住
     来自敌方方向的导弹;不接战时炮塔归位到车头,扇区即车头前方。
   - 渲染:选中装有 IR 的 T84BM,drawSel 画 120° 扇形(半透明橙红 + 虚线边)。

4. 踩坑(真实事故):
   - ★探测代码位置:曾把整段 if(u.ir) 块插入到 unloadTransport 里
     (oldString "if(u.type==='harvester'){" 在卸载函数里也出现),导致干扰完全不
     生效。插代码前先确认目标行是 updateUnit 里的那一个(grep 看出现次数)。
   - 敌我判定用 m.team(发射方队伍),与 APS 一致;测试时"我方"是坦克同队,
     "敌方"才是要干扰的(苏军 T84BM 的敌方 = 盟军导弹)。
   - 被干扰导弹速度沿用原 m.speed(初始 63,加速到 210);16px/步按路程累计,
     走完 3 步约 48px 就炸,所以干扰区是"打乱+快速自毁",不是追着导弹打。
   - 爆炸不分敌我 = 干扰器自己也可能被乱飞的导弹撞到/炸到,这是设计,
     "撞到周围目标也产生伤害"就包含自己。
   - 长钉(spike)绝对不干扰:条件里必须 m.spriteType!=='tow'。

六、空军武器包:A-120c 空对空 / A-174b 空对地(替换原"测试炸弹包")
-------------------------------------------------------------------------------
1. 设计:F16/苏35 战斗机专属武器升级(替换旧的 TOW 炸弹包,旧 PLANE_BOMB 全删)。
   两种可同时装、各自独立弹舱(各 2 发)、各自返回机场补弹。
   - A-120c 空对空:只打飞机;伤200/速180/射程300。
   - A-174b 空对地:只打地面/建筑;伤650/速150/射程310。
   两者共同点(与 TOW 的区别):
     · 不可被红外干扰(T84BM) — IR 条件 spriteType!=='tow',a120c/a174b 天然排除。
     · 不可被 APS 反导 — APS 条件收紧为 m.spriteType==='tow'(原为"非spike")。
     · 不被任何目标挡弹 — updateMissiles 的 m.air 分支不查 atgmBlocker。
     · 本质仍是追踪+命中爆炸 AOE(explodeATGM,范围伤只打敌方地面,飞机免疫)。

2. 常量(config.js):AA_COST/AA_UPGRADE_TIME/AA_AMMO/AA_RANGE/AA_DAMAGE/AA_SPEED/
   AA_SPRITE/AA_SPRITE_LEN(24px)/AG_*(len 28px)/AIR_MISSILE_CD(1.2s)。
   airMissileEffRange(u,base,target)=base + (u.radar?30:0) - (target.coat?50:0)。

3. 弹体:Missile 类加 this.air(空军导弹标记)。launchAirMissile(u,target,kind) 按
   kind 建 Missile 并覆盖 speed/maxSpeed/maxRange/damage,air=true。
   updateMissiles 顶部 if(m.air) 分支:直线追踪(限转角)、加速、超射程自爆、
   atgmHitTarget 命中即 explodeATGM(不查挡弹)。

4. 发射判定(updateAircraft 手动攻击):
   - 目标 fly → 打 A-120c(需 u.aa 有弹,射程 airMissileEffRange(u,AA_RANGE,target))。
   - 目标非 fly → 打 A-174b(u.ag)。
   - 冷却 u.aaCd/u.agCd(1.2s)限速,防止每帧连射清空弹舱。
   orders.js orderAttack 里按 enemy.fly 分流给 aa/ag;giveOrder 里"飞机选择可指定
   敌机为目标"(selHasFly),地面部队仍不能点飞机。

5. 返场补弹(修改后的逻辑):只要 A-120c 或 A-174b 任一弹舱打空 → planeNeedRefuel(u)
   (置 _needRefuel 并 _returning)。强制返航优先级低于玩家指令:玩家中途右键移动
   (orderMove)会先取消立即返场、置 _refuelAfterMove,飞到新盘旋点盘旋约2秒后再
   自动返场。parkAircraft/releaseAircraft 分别补满 aa/ag 弹舱。

6. 渲染:贴图 aim120c_field/aim174b_field(机头朝上,已挖白底),drawMissiles 按
   spriteType 分三种(横向 tow/spike、朝上 a120c/a174b),朝上贴图 rotate(m.ang+π/2),
   长轴按高对齐到 AA_SPRITE_LEN/AG_SPRITE_LEN。

7. UI:选中飞机 4 个安装按钮(A-120c/A-174b/雷达/涂层);右侧机场面板每架飞机也有
   4 个小安装按钮(airPlaneUpgrade(uid,which))。unitStatsHTML 显示各弹舱弹药与冷却。

七、雷达火控(射程+30;自动分配/倾泻攻击模式)
-------------------------------------------------------------------------------
1. 设计:F16/苏35 火控模块。所有己方导弹射程 +30(RADAR_RANGE_BONUS);
   解锁 1号(A-120c)/2号(A-174b) 两个攻击模式按键,按键循环:
     手动(0)→ 自动分配(1)→ 倾泻(2)→ 手动。
2. 常量:AIR_MODE_MANUAL/AUTO/DUMP + AIR_MODE_NAME;RADAR_COST=2500/15秒。
3. 运行(updateAircraft 调 updatePlaneRadarWeapon(u,dt,'aa'/'ag'),仅 u.radar 且
   模式>0 且对应武器已装):
   - 探测圈 = 以自己为圆心、半径=武器有效射程(airMissileEffRange)。
     AA 圈查敌方飞机;AG 圈查敌方地面单位+建筑。
   - 自动:敌人"新进入"圈(上一帧不在)打1发,lastFire[unit]=time;单目标冷却
     AIR_MODE_AUTO_COOLDOWN=2.8s,期间该单位仍在圈内且存活则补刀(未死再打;
     A-120c/A-174b 一致)。手动两发之间仍用 AIR_MISSILE_CD=1.2s。
   - 倾泻:敌人"新进入"圈 → while(有弹) 全部打光(一次齐射)。
   - 每帧重建 cur Set,存回 u.aaScan/u.agScan 作为下帧"上一帧圈内"基准;
     lastFire 用 Map(单位对象做键),死亡/出圈即删。
   - 弹药打光自动 planeNeedRefuel 返场(与手动一致)。
4. 渲染:选中处于自动/倾泻模式的飞机,drawSel 画该武器探测圈虚线圆。

八、涂层更新(敌方雷达式探测 -50)
-------------------------------------------------------------------------------
1. 设计:F16/苏35 被动防御。让本机"进入任何敌方雷达式探测(尤其空对空导弹、
   未来的地对空导弹)时,等效对方探测范围缩小 50px"。
2. 实现:airMissileEffRange 对 target.coat 减 COAT_RANGE_PENALTY(50)。
   即敌方飞机/Auto探测圈对该机的有效射程 = 基础 - 50(雷达+30 在敌方那边照算)。
