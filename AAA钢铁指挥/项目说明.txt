================================================================
钢铁指挥 —— 项目说明（供后续 AI 快速上手）
================================================================

【一句话概述】
纯 HTML+Canvas+原生 JS 实现的即时战略小游戏（仿红警），单页应用，
无构建工具、无依赖、无后端，直接用浏览器打开 index.html 即可运行。

【目录结构】
  index.html            页面入口：两个 canvas(主画面/小地图)、HUD、菜单/帮助/暂停/结束覆盖层
  css/style.css         全部样式
  js/*.js               游戏逻辑（严格按 index.html 里 <script> 的顺序加载）
  img/*.png             建筑素材
  img/units/*.png       单位素材（含坦克照片贴图）
  tools/process-sprite.js  单位照片素材预处理脚本（去背景/裁切/居中）
  img/units/README.txt  素材替换说明
  坦克与步兵战车修改经验.txt  坦克/步战车贴图结构与缩放经验（方向约定、几分之几法则等）
  装甲升级包具体事项.txt  升级包类功能的经验与逻辑（反坦克导弹 TOW/长钉、自主防御系统、T84BM反应装甲/红外干扰）
  飞机与机场修改经验.txt  飞机/机场/飞机升级模块的经验与踩坑（停驻/释放/盘旋/返场/测试炸弹包）
  飞机升级模块.txt  飞机额外升级模块的经验与逻辑（A-120c空对空/A-174b空对地/雷达火控/涂层更新）
  F16战斗机技术文档.txt  F-16 战斗机完整技术文档（属性/机场生产/盘旋/双导弹包/雷达火控/涂层/返场）

  config.js   常量、护甲/弹丸克制、单位/建筑/科技定义、贴图映射、RENDER_SCALE、SPRITE_ROT、升级包常量(ATGM/APS)

  update.js   每帧更新：战斗、寻路、生产、装卸、胜负判定、导弹/拦截弹/自主防御
  render.js   渲染：地形、建筑、单位、弹丸、导弹/拦截弹、特效、小地图、坦克照片贴图

  music.js    背景音乐(4 首 mp3 循环)、开关/持久化、设置弹层入口
  game.js     主循环 frame()、resize()、setupGame()、启动入口

【核心常量与数据结构】
  坐标系：世界 1 单位 = 1 逻辑像素；TILE=32；地图默认 64x48 格（可动态放大）。
  MAP_W/MAP_H/W/H 是 let，由 setMapSize() 按地图设置；逻辑视口用 viewW()/viewH()。
  格子数组（二维，[x][y]）：
    terrain[x][y]   = 'grass' | 'tree' | 'water'
    blocked[x][y]   = true 表示陆地单位不可通行（水/树/建筑占格）
    structBlocked[x][y] = true 仅建筑占格（用于海军/两栖寻路区分"建筑"与"水域"）
  teams：gameTeams[{name,faction,group,ai,spawn}]；teamGroups 决定同盟/敌对；
    teamCol() 蓝=友方阵营、红=敌方阵营；teamColor() 是队伍角标色（9色，不影响蓝/红）。
  阵营：teamFactions[team] = 'allies'|'soviet'；单位外形由各自阵营决定。

【单位/建筑/护甲系统】
  单位定义在 getUnitDefs(faction)（按阵营返回），建筑在 BLD_DEFS。
  弹丸类型：cannon火炮 / bullet子弹 / machinegun机炮 / missile导弹(反坦克导弹,走 MISSILE_MOD 修正表)。
  护甲类型：cloth布甲/steel钢甲/castiron铸铁甲/titanium钛合金甲/concrete混凝土/wood木甲。

【菜单流程(模式选择页 + 遭遇战设置)】
  初始页面 #landing:遭遇战 / 任务模式 / 挑战模式(后两者"敬请期待"),帮助/设置按钮也在此页。
  点「遭遇战」进入原主菜单 #menu(地图/队伍/资金/出生点),与电脑对战。
  game.js showMenu() 从结算页返回的是 #landing(先隐藏 menu 再显示 landing)。

【电脑难度系统(每台电脑独立)】
  gameTeams[t].diff = 'easy' 简单 / 'medium' 中等 / 'brutal' 残酷,主菜单队伍行的「难度」下拉设置。
  影响(见 ai.js initAI / updateAI):
   - 经济收入倍率:简单1.0 / 中等1.6 / 残酷2.3
   - 中等·残酷:建造计划加实验室(lab),自动研发科技(优先 矿石精炼→高级炮台→阵营专属),
     并补第三座发电厂保证实验室 100 电
   - 残酷:队列深度3、训练目标更多、兵力≥2 即进攻、进攻间隔更短(18~26s)
   - 简单:完全保持原版 AI 行为
  把电脑分组设为 组A(同盟) 即作为玩家盟友,其难度设置依然生效(如"中等电脑盟友")。

【背景音乐与设置】
  js/music.js:4 首 mp3(MUSIC_FILES,与 index.html 同目录)按序循环播放——单 Audio 元素,
    'ended' 时切下一首取模循环。musicOn 持久化在 localStorage['ra_music'];
    toggleMusic()/setMusic()/playMusic() 控制;首次 pointerdown 自动开播(绕过自动播放限制)。
  入口:主菜单左上角「设置」+ 暂停页「设置」-> #settingsOv 弹层(openSettings/closeSettings,
    updateMusicUI() 刷新所有 [data-music-toggle] 按钮文本)。

  伤害 = 弹丸伤害 × ARMOR_MOD[护甲][弹丸]；磁暴步兵对布甲 150%。
  科技：RESEARCH_DEFS（发电改进/矿石精炼/高级炮台/贫铀/反应装甲）。
  反应装甲(T90):护盾 300,每秒恢复 15,被打破后也能从 0 重新生成(updateUnit 中
    shield<REACTIVE_SHIELD 即恢复,上限 REACTIVE_SHIELD),另有一次免死 survivedOnce。
   兵营升级解锁 exo(盟军)/magnet(苏军)；战车工厂升级解锁 abrams(盟军)/t90(苏军)、mcv。

【碰撞系统（双圆胶囊 + 刚性,重点）】
  单位碰撞箱仍以半宽/半高 hw/hh(见 config.js 的 UNIT_BOX)表达,但实际碰撞用
  "双圆胶囊(Capsule Approximation)"：colR=min(hw,hh) 为圆半径,头/尾两圆圆心
  距中心 colOff=max(hw,hh)-min(hw,hh)。2×1 坦克(实测贴图≈68x26px,hw=34/hh=13)
  被完美包裹;圆形单位(colOff=0)只用一个圆。Unit.circlesAt()/circles() 取圆。
  组成:
   - separateAll():对非敌对单位按"双圆×双圆两两距离检测"计算分离速度(软,防挤压),
     按圆的重叠量二次衰减推出平滑推力,海量坦克挤在一起绝不穿模/抖动/卡墙。
   - resolveRigid():capsuleOverlap() 取穿透最深的圆对,沿其圆心连线位置修正
     (6轮迭代/每轮重建网格);移动单位优先挤开挡路空闲单位,完全重合随机抖动。
   - 本地脱困:applyMovement 里卡住(stuckT>0.5s)时左右/后小步(8px)找不重叠空位。
   - 静态碰撞:积分时检查胶囊两圆所在格(uBodyBlocked),长车身斜插不进障碍/水面。
  movement 用 arriveDist 判定到达;formationTargets 队形间距按 hw+hh+4 自适应。
  敌人也参与刚性推开(交战时允许少量瞬时重叠)。
  平滑转向:朝向不再瞬间硬转,applyMovement 里用 lerpAngle(u.facing, 目标角,
    TURN_RATE*dt) 插值,产生真实履带战车转向效果(TURN_RATE=6 弧度/秒,见 config)。
  受击反应(灵活不牵制):applyDamage 只把"空闲"单位拉进攻击(存 prevOrder,打完回到原指令);
    已有 移动/撤退/采集 指令的单位不被强制参战,一边走一边对射程内敌人顺路开火
    (move 分支移动射击),撤退时照样能走掉;仅 AI 的"边走边打"(move+x2) 会被拉入战斗。
    空闲单位(idle)感知半径=射程×1.5,附近有敌人会主动迎战(updateUnit 的 none 分支)。

【移动稳健性(卡边缘 / 卡船坞 / 坦克互锁转圈)】
  三处根因与修复(均在 update.js / build.js):
  1) 长胶囊斜贴障碍卡死(水/陆边缘、建筑边缘、船坞边缘):applyMovement 的滑移只试
     X/Y 两轴,斜贴时两轴都被胶囊圆挡住→永久卡死。新增"旋转脱困":stuckT>0.5 且
     当前朝向确实被静态障碍挡住时,在期望朝向附近逐档试 ±30°/±60°/±90°/180°,
     找到一个能让胶囊两圆都落在可通行格、且前方 10px 可行的角度,转到该朝向并
     用 _escapeT=0.6s 的"短暂逃生"保持沿该方向直线滑出,清开障碍后再回归寻路。
  2) 驱逐舰刚造出就卡船坞:spawnUnitNear 对海军单位改为"挑周围 4 邻水格最多的水面"
     (不再只取船坞正下方那格),出生在开阔水面,避免挤进船坞/岛屿窄缝。
  3) 两辆坦克靠一起"转圈圈":两车路径共用同一中间航点,都够不到格中心,分离力把
     它们推成环绕(约 65px 的稳定轨道)。
     修复:
     - 侧向分离力封顶(≤55% 速度),避免被同伴"推着绕圈";
     - followPath 航点到达带 arriveDist 容差,不必精确踩格中心;
     - resolveStuckAfterRigid() 位移检测:0.4s 内有移动意图但位移 <40% 期望(速度被
       分离/刚性修正抵消)→ 侧向滑出;若离当前航点 <110px 却一直没靠近 → 跳过该航点;
     - facing 归一化到 [-π,π],防止慢速转向时角度无限累积(渲染按 facing 旋转,
       累积会表现为原地转圈)。
  选择圈:drawSel 不再画选中单位圆圈;改为选中移动中的陆地单位显示"单位→目标点"的
     虚线 + 准星目标标记(仅非 naval 单位)。

【移动仲裁 + 寻路退避(移植自朋友的优化版,update.js)】
   1) 方向仲裁 arbitrateFlow():每帧在 separateAll 前跑一次。给每次移动/攻击指令分配
      随机优先级 flowPriority()(按 order.x/y 缓存),对头/交叉冲突(方向点积≤0.2 且
      胶囊间距 < r+48)时,低优先级单位被标记 _backing={t:0.9,dir:反方向},在
      applyMovement 里以 0.6 速度持续倒车让行;"后退向后传播":正后方同队单位若把自己
      顶向后退者(方向点积>0.7)也一起后退,避免把让行者顶回死锁点。
   2) 让行 _yieldT:脱困滑开(resolveStuckAfterRigid 横向滑出 / applyMovement 本地脱困)
      后随机暂停 0.4~1.4s,用随机时差打破双向车流的对称死锁(两车互相顶住原地晃)。
   3) 寻路重试退避 pathRetryReady():A* 失败记 _lastPathFail=time,0.7s 内不重复算 A*
      (followPathToEntity / followPathTo 都在重试前检查),避免卡住时每帧全图寻路转圈;
      resolveStuckAfterRigid 里攻击指令被清空路径时也记 _lastPathFail。
   4) 矿车换矿冷却:矿脉被"已停在矿点开采"的其它矿车占用时,持续 2 秒仍未腾开才换矿,
      换不到空闲矿则冷却 1 秒再试,避免两辆矿车互相赶走反复横跳。
   5) 建筑驱逐:markBlocked(b,true) 时 ejectUnitsFromBuilding() 把站在建筑占地格内的单位
      用 nearestOpenCellFor()(由近到远按单位可通行性)推到最近开放空格,避免建筑骑单位。
   6) 鼠标中键按住拖图:input.js button===1 拖拽改 cam(edge 滚动之外的第三种视角方式)。

【海战图:AI 运输艇抢滩(移植自朋友的优化版,ai.js)】
   updateNavalAI(team, st, enemyBase, dt):海战图电脑不再用陆地部队直接过水,而是:
   1) 装船:待命的空运输艇给未登陆的地面战斗单位(非 _aiUnloaded)下 load 指令;
   2) 航行+登陆:乘客上齐或超时后 _aiSail,驶向敌方基地,距敌基地 ≤8 格时 unloadTransport
      (卸载单位打 _aiUnloaded 标记,卸完立即返航回船坞再接下一批);
   3) 已登陆部队 + 驱逐舰每 2 秒重新集结进攻一次(避免每帧全图寻路)。
   配套:st.trainTargets.transport=2、destroyer=2;unloadTransport 里 t._aiTransport 时给
     卸载单位打 _aiUnloaded 标记。

【海军系统（近期新增，重点）】
  船坞 dock：2x2、600金、720血、木甲，只能整块建在水上（canPlaceAt 强制 terrain==='water'），
    且必须距最近己方建筑 ≤8 格（DOCK_BUILD_RANGE,贴近基地下海,不能乱修），
    快捷键 I，生产驱逐舰 destroyer / 运输艇 transport。
  驱逐舰：naval=true，只能在水中航行；火炮 90 伤/射程118/攻速1.2/移速56。
  运输艇：amphib=true，陆海通行；小机枪(子弹10伤/攻速0.6)；capacity=12 运载点。
  通行性：
    unitPassable(u,cx,cy)：structBlocked 挡一切；树挡一切；水只有 naval/amphib 能过；驱逐舰不能上岸。
    pathFor(u,...) 自动为 naval/amphib 走 findPathFor，其余走 findPath。
  spawnUnitNear 统一从建筑"下方那面"出:优先取正下方一行,不足再向下/左右/上方回退
    (驱逐舰出生在水格、运输艇水/陆皆可,与建筑下方水/陆一致)。
  生产队列与普通单位一致：选中船坞点生产按钮，"哪里点建造哪里出"。

【运输艇运载系统】
  cargoUnits[] 存放已装载单位对象；usedCapacity(t) = sum(transportCost(c))。
  transportCost(u)：步兵1 / exo·magnet2 / 矿车·灰熊3 / 犀牛(soviet tank)4 / 基地车·abrams·t90 6；海军不可上船。
  装载：选中地面单位右键点己方运输艇 -> 走"load"指令 -> 靠近自动上船(doBoard)。
  卸载：手动释放——选中运输艇右键地面=仅移动(不自动卸载);到位后选中运输艇点
    「释放部队」按钮 -> manualUnload() 在艇当前位置 unloadTransport() 生成单位。
  渲染：运输艇下方显示 "已用/12"；选中信息面板显示运载量。
  注意：Unit 构造器里 this.cargo=0 是矿车用的(矿石量)，运输艇的运载用 cargoUnits，
    二者不可混用（历史 bug：曾被覆盖导致 crash）。

【地图系统与"海上争霸"】
  每个 MAPS 条目可有 width/height/custom/spawns/islands 字段。
  setMapSize(w,h) 会同步更新 W/H/GRID_COLS/cam.maxX/maxY，切换地图后自动复位。
  海战图 naval：id='海上争霸'，80x56（比默认大），四岛(约20,15 / 60,15 / 20,41 / 60,41)环海，
    出生点按队伍数落在岛上，矿放在岛上。genNavalTerrain() 生成。
  AI 只在 naval 图上建船坞+出驱逐舰（isNaval 判定），普通图不建船坞。

【单位照片贴图（艾布拉姆 / T90）】
  这两辆坦克用玩家提供的照片作为战场本体贴图，不读像素、直接 drawImage：
    drawUnitImg() 按 SPRITE_ROT[u.type] 旋转对齐炮口到朝向前方，再 drawImage。
  预处理(去背景/裁切/居中)在 tools/process-sprite.js 完成，输出到 img/units/。
  背景识别：洪泛填充"与图片边缘相连"的纯黑或纯白区域，绝不删坦克内部内容
    （历史教训：按亮度阈值会误删深色履带导致"缺肉"）。
  SPRITE_ROT：炮管朝左的两张图转角均为 Math.PI；开火炮口闪光画在贴图左侧(-dw/2)。
  替换素材流程：把新照片放 img/units/，用 process-sprite.js 处理，确认 SPRITE_ROT。

【建筑照片贴图（建造厂 / 战车工厂 / 发电站等级 / 兵营 / 精炼厂 / 实验室 / 维修厂）】
  各建筑可用玩家照片做战场本体;发电站按等级分 3 张贴图;兵营/精炼厂/维修厂用独立战场贴图。
  process-sprite.js 支持输出目录参数(默认 img/units)，例：
    node tools/process-sprite.js "建造厂.png" command img 512

【单位光影 / 接地渲染(让坦克"置身于场景中",不悬浮)】
  全部在 render.js 用原生 Canvas2D 实现(等价 PixiJS 的滤镜概念,零依赖):
  1) 接地接触阴影(AO)+ 方向性阴影:照片单位先画一层"与车体足迹(hw/hh)同尺寸"的
     暗色椭圆(drawShadowSprite),紧贴车身正下方、旋转随车头——这是坦克"压在地上、
     不悬浮"的关键(足迹多大阴影就多大,外层再叠更淡更大的 AO 过渡消除硬边);
     再用 bakedShadow()(贴图 source-in 压黑 + 高斯模糊烘焙一次)做方向性剪影阴影,
     整体偏移 UNIT_SHADOW_OFFSET(+5,+8,光在左上方)并按 u.facing+SPRITE_ROT 同步旋转,
     Alpha=UNIT_SHADOW_ALPHA。水上单位(驱逐舰/运输艇)走 drawNavalShadow,只留很淡的
     椭圆投影,避免"黑影贴在水面上"。
  2) 色调对齐：bakedTone() 按 UNIT_TONE_FILTER(等价 ColorMatrixFilter 的
     saturate/contrast/brightness/hue-rotate)把照片烘焙成"融入草地"的版本,
     drawUnitImg 直接绘制烘焙版,零每帧 filter 开销。想微调就在 config.js 改字符串。
  3) 履带/轮子压痕 + 扬尘：移动中的 tank/abrams/t90/harvester/mcv 按走过的距离
     (updateTrackMarks) 在车尾左右两条履带处生成低透明度深色压痕(trackMarks,
     随 life 淡出,上限600),速度较快时喷出 'dust' 淡黄尘土粒子。
  烘焙缓存按 img.src 区分,BAKE_MAX=384(屏幕坦克约68px,省显存且提升 drawImage 性能)。
  调参集中:config.js 【单位光影 / 接地渲染调参】区块。

【已知注意事项 / 坑】
  1. 地图尺寸是动态的：改地图前先 setMapSize，别把 MAP_W/H 当常量硬编码。
  2. canvas.getImageData 在 file:// 下会被浏览器安全策略拦截(SecurityError)，
     所以贴图处理必须放到 Node 脚本里，运行时只 drawImage。
  3. 遍历 units 数组时不要直接 splice（会导致 gridCollect 下标错乱），
     上船/卸载用标记+循环后统一处理，并在 doBoard 后重建 buildGrid()。
  4. Unit.cargo 被矿车占用；运输艇的装载是 cargoUnits，不要混。
  5. orderMove 里不要对自己递归（历史：选中运输艇再点运输艇会死循环栈溢出）。
  6. 单位移动、寻路、出生格都要考虑 naval/amphib，用 pathFor/unitPassable/spawnUnitNear 的分支。
  7. 新增升级包:config 常量 + entities 字段 + build 安装函数 + update 运行时 + ui 按钮
     + input 分发 + 版本号,七处缺一不可;加函数后 grep 一遍引用防漏定义。
  8. 探测型武器(如 APS)对持续在范围内的目标只打一发:用 xxxEngaged 记录已接战目标,
     否则每帧重复发射把弹夹打光。
  9. ★改 UTF-8 中文文件别用 PowerShell 的 Get-Content/Set-Content(按 ANSI 编解码会
     把中文写坏,本项目真实事故),用 Node 或编辑工具。
